# Implementation Record

## 1. Hosting and DNS inventory
The domain and hosting account were already active at MashhadHost. The original DNS zone contained website, mail, authentication, cPanel, discovery, and calendar/contact service records.

Before changing nameservers, the important records were recreated and checked in Cloudflare so the website and mail environment would continue to resolve after the DNS authority change.

## 2. Cloudflare DNS activation
The authoritative nameservers were changed from the hosting provider's pair to the Cloudflare-assigned pair.

After propagation completed, Cloudflare showed the zone as Active.

The website hosting itself was not moved.

## 3. Tunnel creation
A Cloudflare Tunnel named `diaco-accounting` was created from the Cloudflare account-level Networking/Tunnels area.

## 4. Windows connector installation
The Windows 64-bit cloudflared package was installed on the same Windows computer that runs the accounting web application.

Installation was verified with:
`cloudflared.exe --version`

The connector was registered as a Windows service using the tunnel-specific service install command generated by Cloudflare.

Service state was checked with:
`sc query cloudflared`

## 5. Connectivity diagnostics
When the dashboard briefly continued to show a waiting state, the connector was checked locally.

Useful diagnostics included:
`cloudflared tunnel diag`

and the local diagnostics endpoint:
`http://localhost:20241/diag/tunnel`

The connector reported an active connection.

## 6. Public application route
Final public hostname:
`account.diacoelectronix.ir`

Final local service:
`http://127.0.0.1:5000`

The route form initially failed while the service URL ended in a trailing slash. Removing the slash allowed the route to be created successfully.

## 7. External verification
The public hostname was opened from outside the local network and the accounting application's login page was displayed successfully.

## 8. Current state
The remote-access path is operational for testing. Cloudflare Access is intentionally deferred until the application is ready for normal operational users and real data.
